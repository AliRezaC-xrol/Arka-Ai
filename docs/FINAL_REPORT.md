## ۱. خلاصه‌ی اجرایی پروژه (Executive Summary)

پلتفرم **آرکا (Arka)** یک محیط ابری یکپارچه، امن و فوق‌سریع برای گفتگوی چندمدلی با هوش مصنوعی و تولید تصویر است. این سامانه با هدف حذف نیاز به جابه‌جایی میان پلتفرم‌های متعدد هوش مصنوعی و ارائه راه‌حل اختصاصی **BYOK (Bring Your Own Key)** توسعه یافته است. در آرکا، کاربر می‌تواند علاوه بر دسترسی به مدل‌های تجمیع‌شده‌ی سایت (OpenAI، Anthropic، DeepSeek، FLUX و ...)، کلیدهای API اختصاصی خود را با امن‌ترین استاندارد رمزنگاری بانکی (`AES-256-GCM`) در سامانه ذخیره کرده و بدون هیچ‌گونه نشت اطلاعاتی یا قطعی چت از آن‌ها استفاده کند.

### مشخصات فنی هسته سامانه (Tech Stack):
- **فریم‌ورک فرانت‌اند و بک‌اند:** Next.js 15 (App Router با کامپوننت‌های بهینه‌سازی‌شده React 19 و توربوپک)
- **زبان پیاده‌سازی:** TypeScript 5 (تایپ‌سیف کامل در تمام لایه‌ها)
- **پایگاه داده و ORM:** PostgreSQL 16 به همراه Prisma ORM 6.19
- **رمزنگاری و امنیت:** وب کریپتو استاندارد (`AES-256-GCM`) با IV و Auth Tag اختصاصی برای هر کلید؛ الگوریتم امضای نشست `Jose HS256` با کوکی‌های امن `HttpOnly` و `SameSite=Lax` ۳۰ روزه
- **استریمینگ زنده:** پروتکل رویدادهای سرور (Server-Sent Events - SSE) با کمترین تأخیر (Ultra-low latency)
- **طراحی و رابط کاربری:** Tailwind CSS مدرن، فونت‌های بهینه‌شده **وزیرمتن (Vazirmatn)** و **سورا (Sora)**، انیمیشن‌های شتاب‌دهی‌شده سخت‌افزاری با `transform` و `will-change`، بدون وابستگی خارجی در رندر

## ۳. مرور فازهای توسعه (از فاز ۱ تا فاز ۹)

### فاز ۱: احراز هویت اختصاصی با گوگل و مدیریت امن سشن
- ورود مستقیم فقط با یک کلیک از طریق Google OAuth 2.0 بدون نیاز به فرم نام کاربری و رمز عبور.
- ساخت اتمیک حساب کاربری در پایگاه داده جهت جلوگیری از تکرار اکانت در شرایط مسابقه‌ای (Race Condition).
- صدور توکن نشست ۳۰ روزه با کوکی‌های رمزنگاری‌شده `HttpOnly`, `SameSite=Lax`.

### فاز ۲: محیط اصلی چت، استریمینگ و جداسازی کاربران
- استریمینگ بلادرنگ با SSE و شبیه‌سازی تایپینگ نرم.
- نام‌گذاری خودکار هوشمند گفتگوها بر اساس پرامپت اولیه.
- سیستم سنجاق کردن (Pin)، ویرایش عنوان، حذف گفتگو و جداسازی کامل اطلاعات کاربران (User Isolation).
- قابلیت تشخیص خودکار پرامپت‌های تصویری و نمایش کارت استودیو تصویر.

### فاز ۳: پروایدرهای شخصی کاربر (BYOK)
- امکان افزودن بی‌نهایت کلید اختصاصی از OpenAI، Anthropic، Google و اندپوینت‌های سفارشی.
- رمزنگاری تمام کلیدها در سطح پایگاه داده با استاندارد `AES-256-GCM` همراه با IV تصادفی.
- ابزار تست زنده ارتباط کلید پیش از ذخیره‌سازی و ماسک‌کردن کلیدها (`sk-...xxxx`).

### فاز ۴: پنل مدیریت مخفی و داشبورد آمار زنده
- پنهان‌سازی کامل مسیر مدیریت (`/c-xroladi1n`) و بازگرداندن پاسخ ۴۰۴ برای کاربران غیرمجاز.
- سیستم ضد بروت‌فورس (Brute-force protection) با قفل ۱۰ دقیقه‌ای پس از ۵ بار تلاش اشتباه.
- داشبورد آماری لحظه‌ای: تعداد کاربران کل، پیام‌ها، کاربران آنلاین، آپ‌تایم و نمودار روند ثبت‌نام ۳۰ روزه.

### فاز ۵: مدیریت پروایدرهای سایت، سیستم چندکلیدی و فیل‌اور خودکار
- تعریف پروایدرهای سطح سایت و تخصیص چند کلید همزمان با مکانیزم چرخش کم‌بارترین کلید (Least-used).
- سیستم سوییچ خودکار در کسری از ثانیه (Failover Engine) در صورت مواجهه با خطای سهمیه (429 Quota Exceeded) بدون قطعی چت کاربر.
- جمع‌آوری و مصورسازی گزارش تحلیلی مصرف توکن‌ها و درخواست‌ها.

### فاز ۶: مدیریت کاربران، بن و محدودیت زمانی خودکار
- جستجوی پیشرفته کاربران بر اساس نام یا ایمیل فارسی/انگلیسی.
- مسدودسازی دائمی (Ban) با ثبت دلیل و اعمال فوری در لایه سرور بدون اتکا به فرانت.
- اعمال محدودیت موقت (Timeout) با قابلیت بازگشایی خودکار بر اساس زمان سرور بدون نیاز به دخالت ادمین.
- اطمینان از عدم دسترسی ادمین به کلیدهای خام شخصی کاربران در پروفایل.

### فاز ۷: اعلانات و پیام‌های ادمین (سراسری و فردی)
- ارسال پیام‌های همگانی به تمام کاربران یا پیام‌های اختصاصی به یک کاربر خاص.
- صندوق پیام‌های تعاملی در محیط چت با نشانگر پیام‌های خوانده‌نشده.
- ردیابی دقیق وضعیت خوانده‌شدن پیام‌ها توسط ادمین و سیستم حذف ایزوله دو سطحی.

### فاز ۸: نهایی‌سازی هیرو و صفحه لاگین اختصاصی
- ویترین تعاملی ۴ حالته در هیرو با انیمیشن‌های شتاب‌دهی‌شده سخت‌افزاری (`60fps`) و ردیابی اسکرول با `IntersectionObserver`.
- صفحه لاگین تمیز، بدون هیچ فیلد فرم ایمیل یا پسورد با دکمه رسمی ورود با گوگل و گزارش شفاف خطاها.
- ریدایرکت خودکار کاربران واردشده از `/` و `/login` به `/chat` در هر دو لایه میدل‌ویر و سرور کامپوننت.

### فاز ۹: تست نهایی جامع و آزمون فشار یکپارچه
- اجرای سناریوهای آزمون فشار با ۲۵ تا ۵۰ کاربر همزمان، آزمون سوییچ ترکیبی بین پروایدرها در یک گفتگو، تست نفوذ امنیتی (IDOR و نشت کلید)، شبیه‌سازی تب‌های همزمان کاربر بن‌شده و تست ریسپانسیو کراس-براوزر.

- **حداقل رم:** ۲ گیگابایت (پیشنهادی: ۴ گیگابایت برای کامپایل سریع)
- **پردازنده:** ۲ هسته به بالا

### ۲. پیکربندی متغیرهای محیطی (`.env.production`)
فایل `.env.production` را در ریشه پروژه با مقادیر امن ایجاد کنید:

```env

# دیتابیس پستگرس محلی یا ریموت

# کلیدهای امنیتی اختصاصی (حداقل ۳۲ کاراکتر رندوم)
SESSION_SECRET="generate-a-random-64-character-string-for-session-jwt-signing"
ENCRYPTION_KEY="32_CHARACTER_SECRET_HEX_ENCRYPTION_KEY_FOR_AES_GCM"

# کلمه عبور ورود به پنل مخفی ادمین
ADMIN_PASSWORD="YourVeryComplexAdminPassword2026!"

# تنظیمات رسمی گوگل کنسول
GOOGLE_CLIENT_ID="your-google-oauth-client-id.apps.googleusercontent.com"
GOOGLE_CLIENT_SECRET="GOCSPX-your-google-client-secret"
NEXT_PUBLIC_APP_URL="https://yourdomain.com"
```

> **نکته امنیتی:** برای تولید کلید رمزنگاری ۶۴ کاراکتری در ترمینال لینوکس دستور زیر را اجرا کنید:
> ```bash
> openssl rand -hex 32

### ۵. پیکربندی وب‌سرور معکوس (Nginx Reverse Proxy)
فایل کانفیگ `/etc/nginx/sites-available/arka.conf` را با تنظیمات زیر برای پشتیبانی کامل از **استریمینگ بدون بافر (SSE)** ذخیره کنید:

```nginx
server {
    listen 80;
    server_name yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # تنظیمات حیاتی برای استریمینگ آنی SSE بدون بافر
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # غیرفعال‌سازی بافر برای چت زنده
        proxy_buffering off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/arka.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### ۶. بکاپ‌گیری خودکار از دیتابیس (Automated Daily Backups)
یک اسکریپت ساده در `/etc/cron.daily/arka-backup.sh` قرار دهید:
```bash
#!/bin/bash
BACKUP_DIR="/var/backups/arka"
mkdir -p "$BACKUP_DIR"
pg_dump -U arka_user arka_db | gzip > "$BACKUP_DIR/arka_$(date +%Y%m%d_%H%M%S).sql.gz"
find "$BACKUP_DIR" -type f -name "*.sql.gz" -mtime +14 -delete
```
```bash
chmod +x /etc/cron.daily/arka-backup.sh
```
